# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

**GlossNote** is a vocabulary-capture app for readers: while reading a book you log words you don't know, the app defines them (offline from a bundled dictionary, richer once online), and words are filed into per-book folders. The intended differentiator is **crowdsourced discovery** — seeing which words other readers of the same book also looked up.

Naming is deliberately split, so don't "fix" the inconsistencies: the product is GlossNote, the root `package.json` name is `glossnote`, the Expo scheme/slug is `glossnote` and the bundle ID is `com.anonymous.glossnote` — but the GitHub repo is `pphmtrungkin/glossnote` while **workspace packages keep the `@better-vocab/*` scope** (renaming it would churn every import for no product gain), and `bts.jsonc` preserves the original `better-vocab` scaffold command as a historical record.

The first vertical slice is built and working end to end. What actually exists:

- **Domain schema** (`packages/db/src/schema/`) — `book`, `folder`, `word`, `dictionary_entry`, `user_preference`, plus enums (`folder_status`, `capture_method`, `dictionary_source`, `offline_dictionary_tier`). Six migrations are generated, the latest being `0005_add_folder_visibility.sql`.
- **Domain API** (`packages/api/src/routers/`) — `book` (`search`, a server-side proxy to Hardcover — its covers are Open Library links built from the hit's ISBNs by `openLibraryCoverUrl`, never Hardcover's user-uploaded `image`, and `folder.create` stores any other cover URL as null because the `book` row is shared), `dictionary` (`lookup`, AI-written definitions gated by Datamuse, cached into `dictionary_entry`), `folder` (`list`/`create`/`update`/`delete`), `preference` (`get`/`update`) and `word` (`listByFolder`/`search`/`create`/`createMany`/`suggestions`/`quiz`/`update`/`delete`), all `protectedProcedure`. The scaffold's `publicProcedure` `healthCheck` is still there; its `privateData` was deleted.

  `apps/server` is transport only — a Hono app mounting Better Auth and tRPC. New endpoints are tRPC procedures here, not `app.get`/`app.post` in the Hono app; a parallel REST surface would have no consumer (the Expo client speaks tRPC) and would drop the shared types.

  `word.create` and `word.createMany` both go through one private `captureWord`, so the "a client never writes `dictionary_entry`" rule cannot hold for the live save and lapse for the offline flush. `createMany` returns a per-capture `saved`/`dropped` result rather than failing the batch: a folder deleted on another device must not strand every other queued word behind it. `dropped` means never retry; a thrown error means keep the queue.
- **Account management** — Better Auth's `deleteUser` is enabled (`packages/auth/src/index.ts`), gated on the caller's password or a session fresher than a day; the cascades off `user.id` do the rest. Changing an email is deliberately not enabled: Better Auth needs a verification mail and this app has no email sender.
- **Screens** (`apps/native/app/`) — `(tabs)/index` home, `(tabs)/shelf` library, `(tabs)/practise` (waiting words, practise by shelf, mastered words via `word.mastered`), `(tabs)/you` (account, counts, and every setting — there is no separate settings screen), `search` (a stack screen behind Library's magnifier), `folder/[id]` book, `word/[id]`, `review`, `add-word`, `(auth)/index` welcome, `(auth)/sign-in`, `(auth)/sign-up`. All but `add-word` are built from the Claude Design canvas (`GlossNote.dc.html`, 18 screens), in this app's own colours; the design's inert affordances (Scan page, Say it) render disabled, and its unbacked numbers (reading progress, page numbers, streaks, shared-shelf totals) and unbacked screens (camera, tutor chat, feed, discover, profile, offline/downloads/syncing) are omitted rather than invented. The design's three review grades collapse to two, because `word.update` records a review as a timestamp and not a grade. Page themes live in `contexts/app-theme-context.tsx`: the **Ochre spot** scheme (`ochre`, the default, and `dark` as its night half) plus Kindle's White/Sepia/Green pages.
- **On-device SQLite** (`apps/native/lib/local-db.ts`, `glossnote.db`, `user_version` 3) — tables `dictionary` (one table for all three tiers, distinguished by a `source` column: bundled `core`, downloaded `extended`, online-resolved `cached`), `pending_sync`, `app_setting`. Reads and writes go through `apps/native/lib/dictionary.ts`; screens never query it directly.
- **Definition resolution** (`apps/native/hooks/use-definition.ts`) — the one answer to "get me a definition for this term": `dictionary.lookup` whenever `useIsOnline` (`expo-network`) says the device is online, the device tiers when it is offline, when the server fails, or when the server has no entry; server results are written back to the `cached` tier. Returns a `found`/`missing`/`unreachable` union so a screen renders a state rather than merging two query results. Pass `{ online: false }` for list rows, which must not fire a request each.

Known gaps — these are groundwork with no producer yet, so check before assuming a feature works:

- **Book linking only happens at folder creation.** `folder.create` takes the picked Hardcover hit (not a `bookId` — that would be an unvalidated FK from a client) and upserts the `book` row on `(provider, external_id)`. There is deliberately no `folder.updateBook`: `word.bookId` is snapshotted from `folder.bookId` at capture time, so linking a book to an existing folder would strand its earlier words outside the aggregate unless the same transaction also runs `update word set book_id = ... where folder_id = ...`.
**The sharing model — do not break this.** Users share *how often a word was saved*, never *what it means*. Definitions are per-device: resolved from the bundled dictionary offline, or from the server when online. Only counts cross between users — and only from **public** shelves: `folder.visibility` defaults to `private`, `word.suggestions` joins it live (so making a shelf private again takes back its earlier words, unlike the snapshotted `word.contributesToAggregate`, which still applies per word on top), and only the shelf's owner can change it. Long-pressing a shelf opens a HeroUI `BottomSheet` with the visibility choice and delete.

Two rules follow, both asserted by `db:smoke`:
- `word.create` accepts a `definition` from the client and stores it on that user's `word.definitionOverride`. It must **never** write `dictionary_entry`, and it leaves `dictionaryEntryId` null. **Definitions are not user-editable**: the add-word screen shows the resolved definition read-only and sends only that (and only when it matches the exact term saved), `word.update` has no `definitionOverride` field (`db:smoke` asserts an old client's edit is stripped), and a reader's own wording goes in `personalNote`. Only a server-side resolver may fill either. A client-writable shared cache means the first person to capture a term defines it permanently for every other reader.
- `word.suggestions` returns `{term, normalizedTerm, readers}` and nothing else. Adding a definition, sentence, or note column to that result breaks both the privacy model and spoiler safety. **Word recommendations live only in the add-word form** (a product decision — the book page and the tabs recommend nothing). The form lists `word.suggestions`' top five while the Word field is empty, completes from them via the optional `prefix` once two letters are typed (LIKE wildcards escaped, asserted by `db:smoke`), and shows `word.topicWords` — AI-picked words for the book, grouped by subject — while the field is empty. Tapping any recommendation only fills the field. Topic words are generated by `suggestTopicWords` (`enrich.ts`) once per book onto `book.topicWords`, shared by every reader; `book.topicWordsAt` is the marker and lock, claimed before the call like `enrichedAt`; and every word must pass `keepDictionaryWords` (the Datamuse gate), because a prompt doesn't keep invented book words out.

`word.suggestions` is served as a live `count(distinct user_id) ... group by normalized_term` over `word`, excluding the caller's own rows and anything already in the folder. There is deliberately no materialized `book_word_aggregate` table (deleted in `0002`; add one back only if that query shows up in slow logs).
- ~~**No AI enrichment.**~~ — built. `dictionary.lookup` finishes by calling `enrichDefinition` (`packages/api/src/enrich.ts`, the one place an AI provider is called), which writes `exampleSentence`/`usageNote`/`enrichedAt` onto the shared row. Keyed by term, never per user. `enrichedAt` is the marker *and* the lock: it is claimed with a conditional update before the call, so concurrent lookups of a new word buy one enrichment between them — that is what makes "at most one AI call per unique word" hold under concurrency. A failed call releases the claim. Enrichment is optional (`AI_GATEWAY_API_KEY`) and every failure returns the base row: it may never turn a working lookup into a broken one.

  A term with **no** shared row goes through `resolveNewTerm`: **Datamuse decides whether it is a word, the model writes what it means.** A word Datamuse has no exact match for is never sent to the model and returns null — this gate is the spoiler guard, because the prompt alone isn't one: Gemini defined `sietch` from *Dune* on every call at `temperature: 0`. A word the model calls unknown (empty definition) is trusted and also returns null, since Datamuse's sources include fiction (`horcrux`). Otherwise `defineTerm` writes definition, contexts and usage note in one call and the row is inserted already enriched; only a *failed* AI call saves Datamuse's own definition and enriches it afterwards. Datamuse unreachable throws rather than skipping the gate. A new term has no `enrichedAt` to claim, so concurrent lookups share one in-process in-flight promise, and terms either gate rejects are remembered in memory so invented words don't buy a request and a call per lookup — both per-process (`ponytail:` in `routers/dictionary.ts`).

  `dictionary.lookup` is the **only** writer of `dictionary_entry` outside `seed.ts`. Datamuse's `sp` parameter is a *fuzzy* match — asking for `sietch` returns `sketch` — so `pickDefinition` requires an exact word match before accepting a result. Removing that check silently files wrong definitions. No API key is needed before 2027-01-01; after that a free key is required (100k requests/day). Datamuse asks to be acknowledged in app documentation.
- **Usage contexts and the quiz.** Enrichment writes `dictionary_entry.contexts` — invented sentences with the term brace-marked, `"The house had an {eldritch} stillness about it."` — and `word.quiz` turns them into fill-in-the-blank cards over the caller's own words. The braces are the format `parseContext` (`@better-vocab/domain`) owns; three callers read it, so never parse a context by hand. The quiz costs no AI call of its own: contexts sit on the shared term-keyed row, so every card came from that term's one enrichment. Cards exclude mastered words, words with no resolved entry, and entries with no contexts; the sort ends on `word.id` because batch-written words share `createdAt` and a partial order lets the session reshuffle between opens. `app/review.tsx` renders it: one run is fetched once and never refetched mid-session, since a stamped review would otherwise reorder the deck under the reader.
- ~~**The AI columns have no reader.**~~ — fixed. `word/[id]` renders both `exampleSentence` and `usageNote`, and `word.quiz` carries `usageNote` onto the review card's reveal.
- **`pending_sync` has a server, but no producer.** `word.createMany` is the flush endpoint the table was designed for, and it is tested. The device half does not exist: nothing writes a row when a capture happens offline, and nothing calls `createMany` on reconnect. Wiring it needs connectivity detection and a flush trigger in `apps/native`.
- ~~**Nothing writes `source = 'cached'` rows**~~ — fixed. `hooks/use-definition.ts` writes back every server-resolved definition via `cacheDefinition` (`apps/native/lib/dictionary.ts`), so the tier's top priority is now reachable.
- **The dictionary pipeline works, end to end.** `scripts/wordnet-to-dictionary.ts <out-dir> [edition]` pulls the JSON export attached to a tagged Open English WordNet release (`globalwordnet/english-wordnet`, default `2025`) and `scripts/build-dictionary-db.ts <core|extended> <in.json> <out.db>` turns each half into a SQLite asset. One 9.5 MB zip, ~2 seconds; it deliberately does **not** read `src/yaml/*` off `main`, which is 72 requests and a moving target — a pinned edition means a rebuild next year yields the same dictionary. JSON exports start at the 2025 edition; older tags ship only XML and RDF. Current output: **core 74,441 terms / 9.2 MB**, **extended 127,311 terms / 185,129 senses / 25 MB**, merging into the device table in ~270 ms. Two traps the scripts now document in place: `src/sense-orders.csv` is a ~1.3k-row manual sense-order *override*, not the lemma index (`src/yaml/entries-*.yaml` is), and a WordNet example is sometimes an attributed `{source, text}` object rather than a string. Sense rank counts across a lemma's whole entry, not per part of speech — the device index is `(term, source, rank)`, so per-POS ranks would collide at 0 and `INSERT OR IGNORE` would drop senses silently.
- ~~**No bundled `core` dictionary asset ships.**~~ — it ships. `apps/native/assets/dictionary/core.db` is committed, and `installBundledCore` (`lib/dictionary-pack.ts`) merges it once on first launch from `SQLiteProvider`'s `onInit`, with the same `ATTACH` + `INSERT OR IGNORE` as the `extended` pack, recording the row count in `app_setting` under `dictionary.core`. It is not passed as an `assetSource`, and a failed merge is swallowed so the app still starts. `apps/native/scripts/build-dictionary-db.ts` still stamps `user_version = 3` into the asset; that only matters if it is ever opened as the app database itself, but keep it in step with `migrateLocalDb`.
- ~~**The `extended` tier has no way in.**~~ — built. `lib/dictionary-pack.ts` downloads the pack (`expo-file-system`'s `File.createDownloadTask`, with progress) from `EXPO_PUBLIC_DICTIONARY_PACK_URL` and merges it with SQLite's own `ATTACH` + one `INSERT OR IGNORE ... SELECT`, never row-by-row in JS. The pack is built with `source = 'extended'` already stamped, which is what makes the column list line up; the `(term, source, rank)` unique index is what makes a re-run idempotent. Removing it is `DELETE FROM dictionary WHERE source = 'extended'` — the reason the three tier tables were collapsed into one in `0002` of the local schema. Install size and row count are recorded in `app_setting` because `count(*) where source = ...` cannot use that index and would scan the table. `app/(tabs)/you.tsx` drives it: installing also sets `preference.offlineDictionaryTier` to `extended`, since the *pack* is per-device and the *preference* is per-account.
- ~~**`user_preference` has no router.**~~ — fixed. `preference.get`/`preference.update` exist, `get` returns `PREFERENCE_DEFAULTS` without writing a row, and `update` upserts field by field. `app/(tabs)/you.tsx` is the caller; it also hosts sign-out, which used to be a tab-header button of its own.

Future feature work should follow the extension points below (new Drizzle schema files, new tRPC routers merged into `routers/index.ts`, new Expo route groups).

## Commands

Package manager is **Bun** (`bun@1.3.14`), workspaces defined via Bun's `workspaces` object (`apps/*`, `packages/*`) and orchestrated by Turborepo (`turbo.json`). Root `package.json` scripts fan out through `turbo run <task>`, optionally filtered with `-F <package>`:

```
bun install                 # install all workspace deps
bun run dev                 # start all apps (server + native) in dev mode
bun run dev:server          # start only apps/server (bun --hot)
bun run dev:native          # start only apps/native (expo start --clear)
bun run build               # build all apps
bun run check-types         # typecheck every workspace (turbo-fanned)
bun run db:push             # push Drizzle schema to Postgres (packages/db)
bun run db:generate         # generate Drizzle migrations
bun run db:migrate          # run Drizzle migrations
bun run db:studio           # open Drizzle Studio
```

`check-types` fans out to two workspaces only: `tsc -b` in `apps/server` and `tsc --noEmit` in `apps/native`. `apps/fumadocs` names its script `types:check`, not `check-types`, so turbo never picks it up — check the docs site with `bun run build` from `apps/fumadocs`, which also validates every MDX page.

```
bun run db:start            # start the local Postgres container (packages/db/docker-compose.yml)
bun run db:stop             # stop it (keeps the volume; add -v by hand for a clean slate)
bun run db:seed             # write dev fixtures (packages/db/src/seed.ts), local DBs only
bun run db:smoke            # assert the DB + routers behave (packages/api/src/smoke.ts)
```

There is **no lint command** — `turbo.json` declares a `lint` task but no workspace implements it, and no linter (eslint/biome/prettier) is installed. There is also **no unit test suite and no test runner** — `db:smoke` is the only automated check: a self-cleaning script that drives the real `appRouter` against a seeded local Postgres to verify what the schema (not TypeScript) enforces — relation joins, ownership scoping (including that `word.delete`/`folder.delete` refuse another user's row rather than reporting success), the partial unique index on `(user_id, book_id)`, capture idempotency, cascades, the Hardcover book upsert, the enrichment claim on `dictionary_entry`, and the live crowdsourced aggregate query. It also asserts `normalizeTerm` directly, and reads the live `pg_enum` labels back to prove the Postgres enums still match `@better-vocab/domain` — a value added to a domain array without a generated migration fails there. It calls no external service: `mapSearchResults` is exported from `routers/book.ts` precisely so the mapping can be asserted against a fixture without a token or a rate-limited round trip, and the enrichment checks assert the *unconfigured* path (which is also the failure path), skipping themselves when `AI_GATEWAY_API_KEY` is set rather than spending money on a smoke run. It needs `db:start` + `db:seed` first, and it is re-runnable without reseeding. Extend it rather than adding a test framework; don't invent lint or test commands beyond it.

Shared dependency versions are pinned once in root `package.json`'s `workspaces.catalog` and referenced as `"catalog:"` in each workspace's `package.json`.

## Environment setup

No `.env.example` files exist; env vars are validated via zod schemas in `packages/env`:
- `apps/server/.env` — `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `CORS_ORIGIN`, `PORT`, and the optional `HARDCOVER_API_TOKEN` and `AI_GATEWAY_API_KEY` (schema: `packages/env/src/server.ts`). Set `SKIP_ENV_VALIDATION=true` to bypass.

`AI_GATEWAY_API_KEY` powers AI enrichment through [Vercel AI Gateway](https://vercel.com/docs/ai-gateway) and is **server-only by SoftwareSpec §8.1** — the Expo app calls its own tRPC procedures, never a provider — so it must never become an `EXPO_PUBLIC_*` var either. Optional: without it, `dictionary.lookup` still resolves and caches base definitions. The model is one `provider/model` string in `enrich.ts` (`google/gemini-2.5-flash-lite` — a small/fast tier per §8.4, $0.10/$0.40 per million tokens, ~$0.08 per 1,000 new words measured), so switching model or vendor is that line and no new SDK. It was chosen from a live run of 14 cheap gateway models on 2026-09-13, and correctness decided it rather than price: several cheaper models defined book-invented words (`sietch`, `gom jabbar`) from *Dune*, which is a spoiler, and `openai/gpt-5-nano` rejects `reasoning: "none"` with a 400 on every call — so test a replacement with live calls on invented words, not just real ones. Calls run at `temperature: 0`: at the default, the same invented word came back blank on one call and defined on the next, and the first answer is saved for every reader. Slugs must match the catalog exactly; `GET https://ai-gateway.vercel.sh/v1/models` lists them and needs no auth. Cheap models come with quirks: GLM 4.7 FlashX, the previous model, nested the answer under an invented key on about half of calls, which `unwrapWrappedObject` repairs (exported so `db:smoke` asserts it without a call), and ignored `reasoning: "none"`. A gateway account with no purchased credits also can't reach much of the catalog, and rate-limits what it can within a few requests. The AI SDK reads the key from `process.env` itself — `enrich.ts` still checks `env.AI_GATEWAY_API_KEY` first, which is what keeps enrichment optional.

`HARDCOVER_API_TOKEN` powers `book.search` and is **server-only by Hardcover's own rules** — their docs state queries "are not allowed to run in the browser, they must be run in an environment where the token can be kept secure", so it must never become an `EXPO_PUBLIC_*` var. Get one at <https://hardcover.app/account/api>. It is optional: without it `book.search` returns a clean `PRECONDITION_FAILED` and folder creation still works with a typed title. Free tier is 5,000 requests/day, 60/minute, burst 10, and **at most one `search` query per request** — the client debounces via `useDebouncedValue`, so don't batch searches or drop the debounce.

Dev ports: **API 3333** (`PORT`, defaulted in the env schema — not Bun's implicit 3000, which collides with everything), fumadocs 4000, Expo 8081. Three values must agree when the API port changes: `PORT`, `BETTER_AUTH_URL`, and the native app's `EXPO_PUBLIC_SERVER_URL`. Point the dev URLs (including `EXPO_PUBLIC_DICTIONARY_PACK_URL`) at the Mac's Bonjour name, `http://<LocalHostName>.local:<port>` (`scutil --get LocalHostName`), not its LAN IP: the router hands out a new IP every so often, and a stale one leaves every request hanging. The root layout caps its startup wait on the session for exactly that case (`SESSION_WAIT_MS`), opening with the session Better Auth restored from SecureStore when there is one.
- `apps/native/.env` — `EXPO_PUBLIC_SERVER_URL` and the optional `EXPO_PUBLIC_DICTIONARY_PACK_URL` (schema: `packages/env/src/native.ts`).

`EXPO_PUBLIC_DICTIONARY_PACK_URL` points at a plain static `.db` built by `bun run scripts/build-dictionary-db.ts extended <source.json> <out.db>`. It is deliberately **not** served by `apps/server`: tRPC is the wrong transport for a large binary, and a static host keeps the download working when the API is down. Without it, Settings says the pack is unavailable rather than offering a dead button.

## Architecture

Monorepo layout: `apps/*` (deployable apps) + `packages/*` (shared workspace libraries).

- **`apps/server`** — Hono app (`apps/server/src/index.ts`). Mounts Better Auth at `/api/auth/*` and tRPC at `/trpc/*` (via `@hono/trpc-server`). This is just the transport layer.
- **`packages/api`** (`@better-vocab/api`) — the actual tRPC router/context logic, kept separate from the Hono app. `context.ts` builds per-request context by calling `auth.api.getSession()`; `routers/index.ts` exports the single `appRouter` — new feature routers get merged in here.
- **`packages/auth`** (`@better-vocab/auth`) — Better Auth config (`packages/auth/src/index.ts`): Drizzle adapter against `packages/db`, `@better-auth/expo` plugin for native deep-link auth, email/password only (no social providers configured). Exported `auth` singleton is imported by both `apps/server` (mounting the handler) and `packages/api` (session lookup in context).
- **`packages/db`** (`@better-vocab/db`) — Drizzle ORM + PostgreSQL (`drizzle-orm/node-postgres`). Schema lives under `packages/db/src/schema` — Better Auth's `user`/`session`/`account`/`verification` in `auth.ts`, domain tables in `book.ts`/`word.ts`/`dictionary.ts`/`preference.ts`, shared enums in `enums.ts`, all re-exported from `schema/index.ts`. Migrations are in `packages/db/src/migrations`. Note this is the *server* schema; the app also has an unrelated on-device SQLite schema in `apps/native/lib/local-db.ts` — the two are maintained separately and deliberately don't mirror each other.
- **`apps/native`** — Expo app using Expo Router file-based routing under `apps/native/app/`. Talks to the backend via tRPC + TanStack React Query (`apps/native/utils/trpc.ts`, using `createTRPCOptionsProxy` typed against `AppRouter` from `@better-vocab/api`) — not plain REST/fetch. Styling via Uniwind (Tailwind-for-RN) and HeroUI Native components — except text inputs: **every text field is plain React Native through `components/text-field.tsx`** (optional `label`, `error`, `multiline` for note boxes, `large` for the search bar), never HeroUI's `Input`/`TextField`/`TextArea`/`Label`/`FieldError`, so one component owns how a field looks on every page theme. A row of chips that needs a label uses a plain `Text` styled like that component's label.

  **Themes.** `global.css` is the single source: each theme is a `@variant` block setting the custom properties HeroUI Native reads, so overriding them re-skins every component without touching component code. A new theme needs three edits in step — the `@variant` block, `extraThemes` in `metro.config.js`, and `READING_THEMES`/`READING_THEME_META` in `app-theme-context.tsx` — and Metro must be restarted, because the theme union in `uniwind-types.d.ts` is generated from `extraThemes` (it's gitignored; a stale one is what makes `Uniwind.setTheme("ochre")` fail to typecheck). Uniwind's own starting theme is `light` and there is no config option to change it, so the default is applied at runtime in the context's load effect, behind the `isThemeReady` gate `_layout.tsx` holds the splash on.

  **The colour scheme is Ochre spot**: one accent (ochre `#a8560f`, `#d99a52` at night), spent only on the reader's own saved words and the single main action per screen — other readers' data stays muted grey by rule, since crowdsourced counts are reference material rather than the reader's progress. Don't add a second accent.

  The scheme's own names (`bg-primary`, `text-ink`, `text-state-learning`, `rounded-card`) are registered in the same file. Tokens with a HeroUI counterpart are **aliases** — `--color-ink: var(--foreground)` — so they follow the reader's page; never copy the hex in beside them, or one colour gets two spellings that drift. `lib/palette.ts` covers what a className can't reach (StatusBar, SVG, `Animated`), re-exporting `nativewind/theme.ts` rather than restating values; its `usePalette()` reads the app theme context, not RN's `useColorScheme()`, because the theme here is a persisted choice across five pages rather than an OS mirror.

  **The reading face is Source Serif 4** (`app/_layout.tsx` loads five faces: regular, italic, medium, semibold, bold). RN registers each face as its own family, so bold is `font-serif-bold` — never `font-serif font-bold` — and italic is `font-italic`, not the `italic` utility. A face named in `@theme` but not loaded renders as the system serif with no error, so keep the two lists equal. `font-body`/`font-heading`/`font-italic` are the scheme's aliases onto three of them.

  `apps/native/nativewind/` is the scheme as it was handed over — a NativeWind v4 drop whose `tailwind.config.js` and `global.css` do **not** apply here (this is Uniwind + Tailwind v4: CSS-first, no JS config). Only `theme.ts` in it is live, as the source `lib/palette.ts` re-exports.

  **Pull-to-refresh comes from `Container`** (`components/container.tsx`): every scrollable screen gets it by default, and a pull refetches the *active* queries (`queryClient.refetchQueries({ type: "active" })`), so a new screen needs no wiring. The auth screens pass `isRefreshable={false}`. Non-scrollable screens have nothing to pull — which is what keeps `review` from reshuffling its deck mid-run; keep it non-scrollable.

  On-device storage is `expo-sqlite` via `SQLiteProvider` in `app/_layout.tsx`, migrated by `migrateLocalDb` (`lib/local-db.ts`). `lib/folder-status.ts` holds only the labels and chip colours; the status values themselves come from `@better-vocab/domain`.
- **`apps/fumadocs`** — Next.js + Fumadocs docs site (dev port 4000), independent of the product runtime; content under `apps/fumadocs/content/docs/*.mdx`.
- **`packages/domain`** (`@better-vocab/domain`) — dependency-free leaf holding what the server and the app must agree on: `normalizeTerm` (the match key every word/definition join uses), the closed value sets (`FOLDER_STATUSES`, `CAPTURE_METHODS`, `DICTIONARY_TIERS`, `OFFLINE_DICTIONARY_TIERS`, `DICTIONARY_SOURCES`) and `PREFERENCE_DEFAULTS` (which `packages/db` applies as the column defaults and `preference.get` returns for a user with no row — editing one needs a generated migration). It exists because `apps/native` cannot import `packages/db` — that would pull Postgres drivers into the RN bundle — so anything both sides need lives here instead of being retyped. `packages/db` builds its `pgEnum`s from these arrays and `packages/api` builds its `z.enum`s from them, so a value is added in one place. **Never inline `term.trim().toLowerCase()` again**: the asset build script (`build-dictionary-db.ts`) stamps the shipped dictionary with the same function, and a drift between it and the runtime lookups would make every offline lookup miss with no error.
- **`packages/env`** (`@better-vocab/env`) — typed env vars via `@t3-oss/env-core` + zod, split into `./server` and `./native` entry points (see Environment setup above).
- **`packages/config`** (`@better-vocab/config`) — ships only `tsconfig.base.json`, extended by every app/package's own `tsconfig.json`.

Type-safety flows one direction across these boundaries: `packages/domain` (values and the match key, no dependencies) → `packages/db` schema → `packages/auth` (Drizzle adapter typed against it) → `packages/api` (`Context`/`AppRouter` types) → `apps/native` (the `AppRouter` type for its tRPC client, plus `@better-vocab/domain` at runtime). There's no duplicated type definitions across the client/server boundary.

Every mutation on a user-owned row goes through `ownedBy` + `assertOwned` (`packages/api/src/ownership.ts`) rather than composing its own `(id, userId)` predicate. Both produce `NOT_FOUND`, never `FORBIDDEN` — a caller has no business learning that a row exists but belongs to someone else.
