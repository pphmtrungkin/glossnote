Tracked against the Lexishelf user-flow doc, section by section. "Schema only" means the Postgres or on-device tables exist, but no procedure or UI actually uses them yet — a foundation, not a feature.

| Flow section | Status |
| --- | --- |
| Onboarding | Partial — email/password auth works ([Authentication](/docs/authentication)); magic link and OAuth aren't configured. The dictionary bundling pipeline exists but hasn't been run for real, so first-launch download isn't wired up. No onboarding UI. |
| Creating a folder | `folder.create` / `list` / `updateStatus` / `delete` implemented ([API layer](/docs/api-layer)) and wired to the Shelf tab — list, create, status chips, long-press delete. No Hardcover client yet, so folders are title-only and `book` rows can't be populated from a real search ([Book search](/docs/book-search)). |
| Logging a word — offline | The `dictionary_core` → `dictionary_extended` → `cached_lookup` lookup path exists ([Offline dictionary](/docs/offline-dictionary)) and the add-word screen queries it as you type. `pending_sync` table exists, but nothing writes to it or flushes it yet — the capture screen still requires the network to save. |
| Logging a word — online | `word.create` implemented and wired to the add-word modal — accepts a definition from the offline dictionary or typed by hand, or leaves the word "pending" ([Data model](/docs/data-model)). No dictionary-API/AI-definition resolver, no text-to-speech, and voice entry needs an on-device speech-to-text library that hasn't been chosen. |
| Browsing inventory | `word.listByFolder` and `word.search` implemented, behind the folder detail screen and the Search tab. Per-word `mastered` toggle and delete are wired up; no sorting or filtering beyond the term match yet. |
| Crowdsourced discovery | Not implemented — the live, per-book frequency aggregate ([worked example](/docs/data-model#worked-example-logging-a-word)) hasn't been written as a procedure yet. Deliberately not cached, so an offline view never risks showing stale (and potentially spoiler-revealing) results. |
| Review / retention | `word.update` supports toggling `mastered`. No review-session UI, no weekly digest job, no push-sending code (`pushToken` table exists, unused). |
| Settings / account | `userPreference` schema exists and is read by `word.create`. No settings screen, no account-deletion config, no export, no "Sync now" button. |
| Mode indicators | Not implemented — `expo-network` is installed but nothing uses it yet. |

## What this means in practice

The data model — both Postgres and the on-device SQLite schema — was designed section-by-section against the full flow doc, so almost everything above has a home to land in already. The first vertical slice is now walkable end to end: sign in, see your shelf, create a folder, log a word into it, browse and search. What's still missing is the rest of the business logic — a Hardcover client, the sync-flush job, the crowdsourced aggregate query — and the screens that depend on it (onboarding, review sessions, settings). Two items additionally need a library decision before they can be built at all: on-device speech-to-text (voice capture) and a push-notification sending mechanism (weekly digest).
