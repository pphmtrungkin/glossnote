GlossNote is a vocabulary app for readers. You read a book. You find a word you do not know. You save it in the app, and the app tells you what it means.

It works in two ways:

- **Offline** — on a plane with no signal, the app answers from a dictionary stored on your phone.
- **Online** — the app gives a better answer, with an example sentence written by AI.

Every word goes into a folder for the book you are reading.

The main feature that makes GlossNote different is **crowdsourced discovery**. You can see which words *other* readers of the same book also looked up.

## About these docs

These pages describe the code that exists today. They are not a plan for the future.

Each page says clearly which parts are built and which parts are still only an idea. If a page disagrees with the code, the code is right. Please open an issue so we can fix the page.

## The stack

This is a monorepo. A monorepo is one Git repository that holds several projects.

We use Bun to install packages and run scripts. We use Turborepo to run tasks across the projects. The first version was generated by [Better-T-Stack](https://github.com/AmanVarshney01/create-better-t-stack).

| Layer | Choice |
| --- | --- |
| Runtime / package manager | Bun (`bun@1.3.14`), Bun workspaces + Turborepo |
| Backend transport | [Hono](https://hono.dev) |
| API | [tRPC](https://trpc.io) |
| Auth | [Better Auth](https://better-auth.com) |
| Database | PostgreSQL via [Drizzle ORM](https://orm.drizzle.team) |
| Mobile app | Expo / React Native, Expo Router, Uniwind (Tailwind for RN), HeroUI Native |
| Offline storage | `expo-sqlite` (on-device SQLite) |

## Where the code lives

```
apps/
  server/    Hono app — transport only (mounts auth + tRPC, no business logic)
  native/    Expo Router mobile app
  fumadocs/  this docs site (Next.js)
packages/
  api/       tRPC router + context — the actual business logic (plus src/smoke.ts)
  auth/      Better Auth config
  db/        Drizzle schema + Postgres client
  domain/    the match key + shared value sets — no dependencies, imported by both sides
  env/       typed env vars (@t3-oss/env-core), split server/native
  config/    shared tsconfig.base.json
```

`apps/*` are programs you can deploy. `packages/*` are shared libraries. No package is published to npm; they are only used inside this repo.

### Why `apps/server` is so small

`apps/server` only knows how to speak HTTP. It receives a request and passes it to `packages/api`. All the real logic lives in `packages/api`, which knows nothing about HTTP.

This split gives us two things:

1. `apps/native` can reuse the exact same types as the server. It does not need to know that the server uses Hono.
2. If we ever replace Hono with something else, only `apps/server` changes.

### Types flow in one direction

```
packages/domain  →  packages/db  →  packages/auth  →  packages/api  →  apps/native
```

Each package uses the types from the package before it. No type is written by hand twice. If you change a database column, TypeScript shows the error everywhere that column is used.

`packages/domain` is at the start of the chain for one reason. The Expo app cannot import `packages/db`, because that would pull the Postgres driver into the phone app. But both sides still need to agree on some things:

- how a word is normalized before we match it
- which folder statuses are valid

Those shared values live in `packages/domain`, which depends on nothing. See the [changelog](/docs/changelog) for the full story.
