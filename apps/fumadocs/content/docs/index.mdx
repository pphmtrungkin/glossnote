GlossNote is a vocabulary-capture app for readers: while you're reading a book, you log the words you don't know, and the app gives you a definition — offline if you're mid-flight with no signal, richer (AI-enhanced, with an example sentence) once you're back online. Words are organized into per-book folders, and the app's distinguishing feature is **crowdsourced discovery** — seeing which words *other* readers of the same book also had to look up.

This docs site tracks the actual implementation, not the aspirational product spec — every page says explicitly what's built versus what's still a design decision on paper. If a section here gets out of sync with the code, trust the code and file an issue against the docs.

## Stack at a glance

A Bun + Turborepo monorepo, generated by [Better-T-Stack](https://github.com/AmanVarshney01/create-better-t-stack):

| Layer | Choice |
| --- | --- |
| Runtime / package manager | Bun (`bun@1.3.14`), Bun workspaces + Turborepo |
| Backend transport | [Hono](https://hono.dev) |
| API | [tRPC](https://trpc.io) |
| Auth | [Better Auth](https://better-auth.com) |
| Database | PostgreSQL via [Drizzle ORM](https://orm.drizzle.team) |
| Mobile app | Expo / React Native, Expo Router, Uniwind (Tailwind for RN), HeroUI Native, daisyUI palette |
| Offline storage | `expo-sqlite` (on-device SQLite) |

## Monorepo layout

```
apps/
  server/    Hono app — transport only (mounts auth + tRPC, no business logic)
  native/    Expo Router mobile app
  fumadocs/  this docs site (Next.js)
packages/
  api/       tRPC router + context — the actual business logic (plus src/smoke.ts)
  auth/      Better Auth config
  db/        Drizzle schema + Postgres client
  domain/    the match key + shared value sets — no dependencies, imported by both sides
  env/       typed env vars (@t3-oss/env-core), split server/native
  config/    shared tsconfig.base.json
```

The pattern to notice: `apps/server` is deliberately thin. It knows how to speak HTTP (via Hono) and hands every request straight to `packages/api`, which knows nothing about HTTP at all. That split is why `apps/native` can share the exact same `AppRouter` type without caring that the transport happens to be Hono underneath — and why, if this ever moved off Hono, only `apps/server` would need to change.

Type-safety flows in one direction across the whole stack: `packages/domain` (the match key and the shared value sets, no dependencies) → `packages/db` schema → `packages/auth` (Drizzle adapter typed against it) → `packages/api` (`Context`/`AppRouter` types) → `apps/native` (the `AppRouter` type for its tRPC client, plus `@better-vocab/domain` at runtime). Nothing is ever hand-typed twice.

`packages/domain` sits at the bottom of that chain for a specific reason: the Expo app cannot import `packages/db` without dragging Postgres drivers into the React Native bundle, so anything both sides must agree on — how a term is normalized before it is matched, what the valid folder statuses are — needs a home neither side owns. See the [changelog](/docs/changelog) for what moved there and why.
